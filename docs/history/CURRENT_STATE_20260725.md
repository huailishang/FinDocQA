# 项目现状快照 — 2026-07-25

## 一句话状态

比赛阶段停止继续优化和提交，但代码仓库保留为后续金融长文档问答继续演进的基线。

## 当前答题链

题目解析 → 题型/策略识别 → 候选文档范围 → 文档内检索 → 证据窗口选择与压缩 → Claim/选项原子化 → 证据绑定与计算 → 验证/失败分类 → 有界恢复建议 → 答案合同与输出。

## 当前保留的核心能力

1. PDF/结构化解析：MinerU 为主，保留页码、标题、表格与来源血缘；局部异常可使用选择性解析器回退。
2. 候选文档范围：支持题目不直接给 doc_ids 时的候选文档解析与范围传播。
3. 检索与证据：词法/结构信号检索、Evidence Assembly、上下文预算、最小充分证据压缩。
4. 题型策略：复合标签和策略矩阵支持计算、跨文档、比较、排序、否定、时序等组合特征。
5. Claim 验证：Claim 原子化、数值/指标/时间/条件/例外局部绑定，支持 SUPPORT / REFUTE / UNRESOLVED。
6. 计算与多槽输出：金融计算、答案格式校验、Token 账本、正式输出合同。
7. 失败与恢复：缺证、血缘、Binding、计算 Binding、模型输出、Provider、预算、运行完整性分流；默认 fail-closed，仅输出有界恢复建议。

## 当前明确不做

- 不再保留逐轮 Pxx runner、audit 和 handoff；
- 不保存 Provider 原始响应和运行 checkpoint；
- 不把排行榜反馈写成生产规则；
- 不允许 qid 或答案硬编码进入通用模块；
- 默认不调用真实 API、不运行 Full100、不生成新正式提交。

## 后续优化优先方向

PDF 页面质量与多解析器 → Embedding / Rerank 或更强混合检索 → 多文档证据完整性 → 动态上下文压缩 → Claim 级验证与二次检索 → Prompt Registry / 离线 A/B → Agent 化的受控恢复循环。

- 真实提交 CSV 和逐题 Provider 输出不进入 FinDocQA Public 仓库。
- 本文件仅保留能力状态，不作为比赛成绩或提交物存档。
