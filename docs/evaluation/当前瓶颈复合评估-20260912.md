# FinDocQA 当前瓶颈复合评估｜2026-09-12

## 结论先行

当前第一瓶颈仍然是 `B-03 问题 → 可靠证据`，但它已经不能再概括成“Retriever(检索器)效果差”。结合 H-35～H-53 的 fresh(全新样本)证据，瓶颈应上移为：

> **FinDocQA 过早把不同检索通道压缩成固定 Top5，导致互补证据在验证前发生竞争和丢失；而当主要通道都失败时，现有通用 Gap-driven Exploration(按缺口探索)又没有形成稳定、已接主链的恢复机制。**

因此下一阶段不应继续围绕 BM25 权重、停用词、邻页半径或单个 query rewrite(查询改写)做微调，而应验证：

```text
问题
→ 多通道候选证据（lexical / semantic / structure）
→ Bounded Evidence Workspace（有界证据工作区）
→ Evidence Sufficiency（证据充分性）
→ 缺口明确时再做 targeted exploration（定向探索）
→ Late Contraction（后收敛）
→ EvidenceBundle / Solver / Answer
```

## 一、P0 主瓶颈：B-03 证据定位与组合架构

### B-03A｜第一轮 Page/Evidence Localization（页面/证据定位）不稳定

H-53 是最直接的新证据：正确 document identity(文档身份)已经固定，但 canonical lexical Top5 在 12 个全新 FinanceBench case 上仍为：

```text
lexical Top5 = 0/12
```

这说明当前主要失败已经不是“文档找错”，而是：

```text
正确文档已经知道
→ 仍然找不到正确页面 / 财务事实 / 表格证据
```

trace 中可看到大量 common/function words(常见功能词)和公司名参与 lexical score(词法打分)，真正需要的 statement / metric / operand(报表 / 指标 / 操作数)没有稳定取得排名优势。但历史 H-35/H-36/H-37/H-41/H-43 已经证明，继续通过 lexical hybrid、BM25 修正、静态 Query Planning、Know-where Lite 或历史 cohort planner 调整，并不能稳定跨新文档族泛化，因此这里不应重新退回微调词权重。

### B-03B｜固定 Top5 发生过早压缩，互补通道证据被丢弃

H-50 对 H-44/H-46/H-49 共 46 个已冻结 case 的独立汇总：

```text
BOTH_HIT      = 9
LEXICAL_ONLY  = 3
SEMANTIC_ONLY = 16
BOTH_MISS     = 18

lexical hit = 12/46
semantic hit = 25/46
lexical ∪ semantic oracle coverage = 28/46
```

因此：

- lexical 单独会丢掉 16 个 semantic-only case；
- semantic 单独会丢掉 3 个 lexical-only case；
- 两个通道不是简单的“谁替代谁”，而是存在真实互补；
- lexical + semantic 的 Top5 union 平均只有约 `8.98` 个 unique pages，范围仍然是有界的。

H-46 证明 pure semantic replacement(纯语义替换)会把已有 lexical correct evidence 挤出 Top5；H-49 又证明 fixed RRF60(固定倒数排名融合)会把部分 semantic-only Gold 从最终 Top5 再挤出去。因此当前更根本的问题是：

> **我们把候选证据过早压缩到一个统一 Top5，然后才做验证。**

更合理的下一架构假设应是先保留 bounded multi-lane workspace(有界多通道证据工作区)，再让证据充分性/验证层决定怎么收敛，而不是让不同 Retriever 在验证前直接竞争五个槽位。

### B-03C｜两条主要通道都 miss 时，缺少已验证的通用 Exploration Runtime（探索机制）

即使保留 lexical + semantic：

```text
BOTH_MISS = 18/46
```

约 39% 的历史跨 cohort case 仍然需要第二阶段探索。

项目并非完全没有这类能力：

- `FinancialEvidenceCompletionAdapter` 已接入 financial report claim 主链；
- `assess_evidence_sufficiency` 已能确定性识别 missing doc / unresolved option / missing semantic atom / missing formula operand 等 gap(缺口)；
- `GapDrivenEvidenceController` 已有通用状态骨架，但当前没有发现产品主链调用点。

所以这里不是“从零造 Agent Runtime”，而是缺：

> **把多通道 Evidence Workspace → Evidence Sufficiency → targeted exploration 这条链真正连接起来，并证明它在 fresh case 上有用。**

H-52/H-53 的邻页扩展就是一次最小探索机制验证：

```text
H-52 observed diagnostic: 3/13 recovered / 2 docs
H-53 fresh:               2/12 recovered / 2 docs
平均额外页面:             12.75 / case
资格门:                   >=3 recovery
结果:                     NOT_QUALIFIED
```

因此 blanket neighbor expansion(无差别邻页扩展)正式停止。探索必须由缺口驱动，而不是简单扩大上下文。

## 二、P1 次瓶颈：B-06 E4 / Freeform Answer Evaluation（端到端答案评估）

B-06 仍然存在，但当前仍排在 B-03 后面。

已经完成的部分：

- Local Gold / Evaluation Suite 已经形成；
- FinanceBench 外部轨接入完成；
- layered semantic review(分层语义评估)规则与 offline harness(离线评估框架)已有；
- known-wrong freeform Judge 有 3/3 agreement。

仍缺：

```text
independent known-correct freeform coverage
+ 更稳定的 semantic Judge authority
+ 当前产品链端到端 Answer/Evidence/False Accept/False Reject/Cost 基线
```

但 H-33、H-53 都表明大量问题在答案生成之前就已经丢掉官方 evidence，所以现在继续扩大 Judge 本身不会解决主要损失。

结论：

```text
B-06 = SECONDARY_BLOCKED_BY_B03
```

一旦 B-03 evidence reach 明显提升，B-06 会重新成为第一批需要恢复的验证瓶颈。

## 三、P2 观察项：B-05 Complex Table Parsing（复杂表格解析）

现象很大，但“这些未解析表格到底造成多少真实问题级失败”仍没有量化，因此目前不能因为数量大就直接把 Parser(解析器)提为第一瓶颈。

结论：

```text

```

未来如果 B-03 的 BOTH_MISS / evidence gap 显著集中到 image table / span table，再把 B-05 升级为 ACTIVE。

## 七、下一步不应该做什么

暂时停止：

```text
继续调 BM25 / stopword / lexical 权重
继续调 RRF 权重
把 radius=2 改成 radius=4
继续从旧 cohort 找“看起来能恢复”的题
单独扩 Judge case 数量
直接建设一个庞大的通用 Agent Runtime
```

这些要么已经有 negative generalization evidence(负泛化证据)，要么绕开了当前第一损失层。

## 八、下一步应该验证的架构假设

建议下一主假设上移为：

> **Bounded Multi-lane Evidence Workspace + Late Contraction（有界多通道证据工作区 + 后收敛）**

大白话就是：

```text
不要让 lexical / semantic 先抢 5 个坑位

而是：
lexical 候选 ─┐
semantic 候选 ├→ 先放进一个最多约 10 页的证据工作区
structure 候选 ┘
                  ↓
       Evidence Sufficiency / Binding
                  ↓
        已够 → 收敛并求解
        不够 → 明确缺什么，再定向补证
```

这条路线同时解释了当前三类证据：

1. semantic 能恢复大量 lexical miss；
2. lexical 又有 semantic 会丢掉的 protected evidence；
3. 单纯扩大邻页虽然能偶尔恢复，但噪声/成本太高，需要由 evidence gap 来决定“补哪里”。

这比继续寻找一个“万能 Retriever”更符合目前项目实证。
